Local-first · Dependency-free · No telemetry

The context file has become a database

So treat it like one.

Static instruction files accumulate stale guidance, hide important constraints, and give teams no useful serving history. Recent research also finds that longer context files can reduce agent performance instead of improving it.

Read the context-file study →

Context that ages honestly

A visible lifecycle, not silent rot.

New context starts active. Full reads extend its useful life. Unused entries become ambient for review, then move into a retained archive. Pin the few things that must never decay.

  1. ActiveServed by default
  2. AmbientWaiting for review
  3. ArchivedRetained, not served

One small loop

Maintain it. Teach agents to use it. Audit what was served.

01

Maintain project context

Add, view, update, and pin knowledge through a CLI designed for scanning.

02

Give every agent a map

Generate small, static guides for Codex, Claude, and Cursor. The project knowledge stays inside agenctx, where it can evolve.

03

Audit the delivered context

List agent sessions by task and inspect a receipt to see each preview and full entry served, in order.

Receipts prove delivery, not model understanding or compliance.

Two-minute setup

Start with the context you already have.

Initialize agenctx, import an existing Markdown file, inspect the result, and generate the lightweight guides your agents will discover.

$ npm install -g agenctx
$ agenctx init
$ agenctx import AGENTS.md
$ agenctx view
$ agenctx dump
